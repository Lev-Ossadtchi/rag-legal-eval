# RAG по закону: поиск нормы, который проверен цифрами

Поиск по тексту закона так, чтобы ответ ссылался на конкретную статью, а качество
поиска было измерено, а не заявлено. Собрано на 127-ФЗ «О несостоятельности
(банкротстве)»: 494 статьи, 1,68 млн знаков.

Работает офлайн: и поиск, и модель эмбеддингов локальные. Для юридических
документов это обычно обязательное условие — текст никуда не уходит.

## Что получилось

40 вопросов, эталон — статья, из которой вопрос составлен.

| Вариант поиска | Нужная статья первой | В первых трёх | В первых пяти | MRR |
|---|---|---|---|---|
| Лексический (BM25) | 32 % | 50 % | — | 0,44 |
| Смысловой (эмбеддинги) | 40 % | 65 % | — | 0,54 |
| **Гибрид (α = 0,7)** | **42 %** | **75 %** | **88 %** | **0,60** |

Что здесь важно: гибрид лучше каждой из частей по отдельности. Лексический поиск
находит, когда в вопросе есть термин нормы («конкурсная масса»), смысловой — когда
человек спрашивает бытовыми словами («когда гражданина перестают заставлять платить»).
Промахиваются они на разных вопросах, поэтому вместе дают больше, чем по отдельности.

**88 % в первых пяти** — практическая цифра: именно пять документов обычно кладут
в контекст модели, которая формулирует ответ.

## Что не работает

Честно, потому что это важнее красивых чисел:

* **5 вопросов из 40 не находятся вовсе.** Например, «какие активы должника подлежат
  реализации» не выводит на ст. 131 «Конкурсная масса»: в вопросе нет ни одного слова
  из статьи, а смысловая близость проигрывает более длинным статьям о реализации.
* **Настройка параметров почти не помогает.** Перебор веса заголовка и штрафа за длину
  дал MRR 0,44 → 0,47. Потолок лексического поиска здесь низкий, и только эмбеддинги
  сдвинули результат.
* **Набор вопросов синтетический**: их сформулировала модель по тексту статей. Это
  проверяет поиск, но не заменяет вопросы живых пользователей — на реальных запросах
  цифры будут другими, и мерить надо заново.
* Один вопрос из сорока сгенерировался с браком (обрывок рассуждения модели).
  Не удалял: в отчёте должно быть видно, как набор получен.

## Как запустить

```bash
pip install -r requirements.txt
python fetch_corpus.py      # корпус из Викитеки: 494 статьи
python make_questions.py 70 # набор вопросов (нужен ключ OpenRouter)
python hybrid.py            # замер всех вариантов поиска
```

Поиск по одному запросу:

```bash
python search.py "кто отвечает за сохранность имущества должника"
```

## Устройство

| Файл | Что делает |
|---|---|
| `fetch_corpus.py` | Забирает закон из Викитеки и режет по статьям |
| `search.py` | Лексический поиск BM25 с русской морфологией |
| `hybrid.py` | Гибрид: BM25 + локальные эмбеддинги multilingual-e5 |
| `evaluate.py` | Замер: Recall@1/3/5, MRR, разбор промахов |
| `tune.py` | Подбор параметров с замером каждой конфигурации |

Решения, которые стоит объяснить:

* **Режем по статьям, а не по абзацам фиксированной длины.** В праве ответ обязан
  ссылаться на статью, и статья — естественная единица поиска. Нарезка «по 500 символов»
  рвёт норму посередине и делает ссылку бессмысленной.
* **Морфология обязательна.** Без приведения к начальной форме «должника» и «должник» —
  разные слова, и поиск разваливается на первом же запросе.
* **Заголовок статьи весит больше текста**: он прямо называет её предмет.
