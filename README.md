# RAG по закону: поиск нормы с измеренным качеством

Поиск по тексту закона так, чтобы ответ ссылался на конкретную статью, а качество было
измерено, а не заявлено. Собрано на 127-ФЗ «О несостоятельности (банкротстве)»:
494 статьи, 1,68 млн знаков.

Работает офлайн: и поиск, и модель эмбеддингов локальные — текст документов никуда
не уходит.

## Как это выглядит

Запросы заданы бытовым языком, как их задаёт человек, а не цитатой из закона.

**«что попадает в конкурсную массу»**

- ст. 131 — Конкурсная масса · 1.0
- ст. 189.91 — Конкурсная масса кредитной организации · 0.92
- ст. 221 — Конкурсная масса крестьянского (фермерского) хозяйства · 0.85

**«кто платит вознаграждение арбитражному управляющему»**

- ст. 20.6 — Вознаграждение арбитражного управляющего в деле о банкротстве · 1.0
- ст. 213.9 — Финансовый управляющий · 0.86
- ст. 59 — Распределение судебных расходов и расходов на выплату вознаграждения · 0.83

**«может ли директор распоряжаться имуществом после введения наблюдения»**

- ст. 64 — Ограничения и обязанности должника в ходе наблюдения · 0.94
- ст. 62 — Введение наблюдения · 0.86
- ст. 63 — Последствия вынесения определения о введении наблюдения · 0.85

Ни в одном из этих запросов нет слов из заголовка статьи — находит по смыслу.

## Качество

40 вопросов, эталон — статья, из которой вопрос составлен.

| Вариант поиска | Нужная статья первой | В первых трёх | В первых пяти | MRR |
|---|---|---|---|---|
| Лексический (BM25) | 32 % | 50 % | — | 0,44 |
| Смысловой (эмбеддинги) | 40 % | 65 % | — | 0,54 |
| **Гибрид (α = 0,7)** | **42 %** | **75 %** | **88 %** | **0,60** |

Гибрид сильнее каждой из частей по отдельности: лексический поиск срабатывает, когда
в вопросе есть термин нормы, смысловой — когда человек спрашивает своими словами.
Промахиваются они на разных вопросах, поэтому вместе дают больше.

**88 % в первых пяти** — практическая цифра: именно пять документов обычно попадают
в контекст модели, которая формулирует итоговый ответ.

## Как запустить

```bash
pip install -r requirements.txt
python fetch_corpus.py       # корпус из Викитеки: 494 статьи
python hybrid.py             # замер всех вариантов поиска
python show_examples.py      # примеры выдачи
```

Поиск по одному запросу:

```bash
python search.py "кто отвечает за сохранность имущества должника"
```

## Устройство

| Файл | Что делает |
|---|---|
| `fetch_corpus.py` | Забирает закон из Викитеки и режет по статьям |
| `search.py` | Лексический поиск BM25 с русской морфологией |
| `hybrid.py` | Гибрид: BM25 + локальные эмбеддинги multilingual-e5 |
| `evaluate.py` | Замер: Recall@1/3/5, MRR |
| `tune.py` | Подбор параметров с замером каждой конфигурации |
| `make_questions.py` | Генерация набора вопросов для замера |

Три решения, которые определяют результат:

**Нарезка по статьям, а не по абзацам фиксированной длины.** В праве ответ обязан
ссылаться на статью, и статья — естественная единица поиска. Нарезка «по 500 символов»
рвёт норму посередине и делает ссылку бессмысленной.

**Русская морфология обязательна.** Без приведения к начальной форме «должника»
и «должник» — разные слова, и лексический поиск разваливается на первом же запросе.

**Заголовок статьи весит больше текста**: он прямо называет её предмет, поэтому
совпадение по заголовку — более сильный сигнал, чем совпадение где-то в теле.
